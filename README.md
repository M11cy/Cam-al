# Мониторинг рабочего места через камеру

Локальный Python-прототип для камеры Mac или Windows. Приложение подключается к видеопотоку, отслеживает сотрудника в выбранной рабочей зоне и показывает тревоги, если сотрудника нет на месте или если он долго смотрит в телефон.

## Что умеет

- определяет, находится ли сотрудник в рабочей зоне;
- запускает тревогу, если сотрудник отсутствует дольше заданного времени;
- ищет телефон рядом с рукой сотрудника;
- оценивает позу сотрудника через pose-модель;
- учитывает наклон головы вниз как дополнительный признак того, что человек “залип”;
- запускает тревогу, если подтверждённый телефон виден дольше 60 секунд.

Приложение использует две модели YOLO:

- `yolov8s.pt` - поиск человека и телефона;
- `yolov8n-pose.pt` - определение ключевых точек тела: голова, плечи, локти, запястья.

Если рядом есть локальная обученная модель `models/shop-camera-phone.pt`, приложение автоматически использует её вместо `yolov8s.pt`.

Для кастомной обученной модели поддерживается упрощённая схема классов:

- `person` - сотрудник;
- `phone` - телефон;
- `other_object` - похожий предмет, который не должен запускать тревогу.

Класс `other_object` можно использовать для вейпов, расчёсок, банок, упаковок и других предметов, которые модель путает с телефоном. Такие объекты отображаются серым и не запускают таймер телефона.

Серые рамки на видео означают неподтверждённые кандидаты на телефон. Красная рамка `phone in hand` означает, что объект прошёл scoring-фильтр и запускает таймер тревоги.

Для телефона используется система баллов и обязательные условия. Приложение учитывает уверенность модели, форму объекта, положение в рабочей зоне, близость к сотруднику, близость к руке и наклон головы вниз. По умолчанию телефон подтверждается только если объект рядом с рукой и голова сотрудника наклонена вниз. У серых кандидатов выводится причина, почему они не были подтверждены.

## Запуск

macOS/Linux:

```bash
./run.sh
```

Если камера не открылась, попробуйте другой индекс:

```bash
./run.sh --camera 1
```

Windows:

```bat
run.bat
```

Если камера не открылась, попробуйте другой индекс:

```bat
run.bat --camera 1
```

На macOS может потребоваться разрешить Terminal/Python доступ к камере:

```text
System Settings -> Privacy & Security -> Camera
```

На Windows может потребоваться разрешить доступ к камере в настройках:

```text
Settings -> Privacy & security -> Camera
```

## Управление

- `r` - выбрать рабочую зону мышкой;
- `s` - сохранить текущую зону в `config.json`;
- `q` или `Esc` - выйти.

## Обучение и дообучение

Ветка `dev` содержит рабочий цикл для дообучения YOLO под конкретную камеру. Модель не обучается с нуля: сначала берётся готовая `yolov8s.pt`, затем она дообучается на кадрах с вашего рабочего места.

Классы датасета:

- `person` - сотрудник;
- `phone` - телефон;
- `other_object` - похожий предмет, который модель не должна считать телефоном.

Общий цикл такой:

1. Собрать кадры с камеры.
2. Создать черновую авторазметку.
3. Проверить и исправить рамки вручную.
4. Дообучить модель.
5. Положить лучший `best.pt` в `models/shop-camera-phone.pt`.
6. Повторить цикл на новых ошибочных кадрах, если точности не хватает.

Сбор кадров:

```bash
.venv/bin/python tools/capture_frames.py --camera 0 --count 300 --interval 1
```

Авторазметка готовой YOLO-моделью:

```bash
.venv/bin/python tools/auto_label_dataset.py --model yolov8s.pt --imgsz 960
```

Скрипт создаёт черновые labels в `dataset/labels_draft`. Это не финальная разметка, а подсказка для ручной проверки.

Проверка и исправление разметки:

```bash
.venv/bin/python tools/annotate_dataset.py
```

Редактор автоматически подгружает рамки из `dataset/labels_draft`. Их нужно поправить, удалить лишние и добавить пропущенные объекты. На каждом кадре желательно размечать все видимые объекты классов `person`, `phone` и `other_object`, иначе неразмеченный объект будет восприниматься моделью как фон.

Клавиши редактора:

- `p` - выбрать класс `person`;
- `t` - выбрать класс `phone`;
- `o` - выбрать класс `other_object`;
- `u` - отменить последнюю рамку;
- `c` - очистить все рамки на текущем кадре;
- `n` - сохранить кадр и перейти дальше;
- `s` - сохранить кадр без объектов;
- `q` - выйти.

Первое дообучение:

```bash
.venv/bin/python tools/train_custom_model.py --model yolov8s.pt --epochs 80 --imgsz 960 --batch 4 --device 0
```

Следующую итерацию можно дообучать уже от предыдущей модели:

```bash
.venv/bin/python tools/train_custom_model.py --model runs/detect/shop-phone/weights/best.pt --epochs 50 --imgsz 960 --batch 4 --device 0 --name shop-phone-v2
```

Подключение готовой модели:

```bash
mkdir -p models
cp runs/detect/shop-phone/weights/best.pt models/shop-camera-phone.pt
```

После этого приложение автоматически использует `models/shop-camera-phone.pt` вместо `yolov8s.pt`.

Ориентиры по количеству кадров:

- 200-500 кадров - первый рабочий тест;
- 1000-3000 кадров - стабильнее для одной камеры и одного рабочего места;
- больше кадров нужно, если меняются люди, освещение, ракурс, одежда, типы телефонов и похожие предметы.

Подробная инструкция лежит в `TRAIN_CAMERA_MODEL.md`.

## Настройки

После нажатия `s` приложение сохраняет `config.json`. В нём можно менять:

- `absence_seconds` - через сколько секунд отсутствия сотрудника включать тревогу;
- `phone_alert_seconds` - через сколько секунд видимого телефона включать тревогу, по умолчанию `60`;
- `inference_confidence` - минимальный порог поиска кандидатов YOLO;
- `object_img_size` - размер изображения для поиска человека и телефона;
- `pose_img_size` - размер изображения для pose-модели;
- `confidence` - порог уверенности для человека;
- `phone_confidence` - порог уверенности для телефона;
- `phone_confirm_score` - минимальный итоговый score для подтверждения телефона;
- `phone_min_area_ratio` / `phone_max_area_ratio` - допустимый размер рамки телефона;
- `phone_min_aspect_ratio` / `phone_max_aspect_ratio` - допустимая форма рамки телефона;
- `phone_person_zone_scale` - насколько близко телефон должен быть к сотруднику;
- `keypoint_confidence` - порог уверенности для точек тела;
- `head_down_ratio` - чувствительность определения наклона головы вниз;
- `phone_hand_distance_ratio` - насколько близко телефон должен быть к запястью или локтю;
- `require_head_down_for_phone` - обязательно требовать наклон головы вниз для подтверждения телефона;
- `require_phone_near_hand` - обязательно требовать телефон рядом с рукой для подтверждения телефона.

## Недоработки

- Модель иногда определяет как телефон похожие небольшие предметы: расчёску, вейп, банку или упаковку. При этом человек явно не будет долго смотреть на такие предметы, поэтому сейчас ложные срабатывания частично отсекаются таймером, проверкой положения руки и наклоном головы.
- Для высокой точности в реальном магазине модель лучше дообучить на кадрах именно с этой камеры и с реальными предметами на рабочем месте.
- Если камера стоит далеко или под неудобным углом, pose-модель может хуже видеть кисти, локти и наклон головы.
- Текущая версия не сохраняет историю тревог и не отправляет уведомления, а только показывает статус в окне.
